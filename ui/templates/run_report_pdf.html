Methodology

MPAC applies the same quality measurement process that human safety teams have used for decades, adapted for AI. When new human moderators ramp up, they're given tests like this until they're aligned with more experienced reviewers. MPAC runs the same process, at scale, across all models.

1
Assemble a golden set
Expert-vetted items with multi-rater agreement. Each item has a canonical correct answer established by human review, not AI judgment. MPAC's built-in library draws from sources like the Gab Hate Corpus and academic datasets; you can bring your own.
2
Zero-shot, pass@1
Each model receives the same instruction prompt and content item; no examples, no fine-tuning, no special treatment. One response per item (pass@1), matching live classifier conditions. This is the baseline; you can layer in prompting or fine-tuning later to measure improvement.
3
Multi-model execution
All selected models run against the same items under comparable conditions. Local models via vLLM; remote models via their native APIs or OpenRouter. Results are never cross-contaminated between models.
4
Standardized scoring
Model responses are extracted and compared to the canonical answer. MPAC computes precision, recall, F1, refusal rate, time to first token (TTFT), output tokens/sec (TPS), end-to-end latency (p50/p95), and cost per model, weighted by sample composition. The result is an apples-to-apples comparison across models, providers, and modalities.

Core Concepts

Key terms used throughout this report.

Test
A named collection of items and a methodology. Evaluation tests score each model response against a known correct answer (precision/recall/F1). Survey tests collect open-ended model responses when a correct answer is not known and score them using consensus and inter-rater reliability methods.
Test Item
A single prompt within a test: a piece of content to classify, a question to answer, or a scenario to evaluate. Items can include text, images, audio, and video. Evaluation items carry a canonical answer from a human expert or multi-rater process.
Test Run
An execution of a test across one or more models. Every model gets the same prompt under the same conditions. Each run records every answer alongside precision, recall, F1, refusal rate, time to first token (TTFT), output tokens/sec (TPS), end-to-end latency (p50/p95), token usage, and cost per model.
Model
A specific LLM identified by provider and model ID. MPAC supports commercial APIs (OpenAI, Anthropic, Mistral), open-source models (Llama, Qwen, DeepSeek), and private or on-prem deployments via vLLM, ollama, and llama.cpp.
Backend
An inference endpoint that routes requests to models: OpenAI, Anthropic, OpenRouter, vLLM, Ollama, Llama.cpp, and more are all available options. Admins register backends; MPAC handles routing, concurrency, and rate limiting automatically. Mix and match local and remote models in the same run!
Metrics
MPAC reports both classic ML metrics and modern LLM performance stats.

Metric Definitions

Precision Of all positive predictions, how many were correct?
Recall Of all actual positives, how many were found?
F1 Harmonic mean of precision and recall. If you're going to read one quality metric, choose this one.
TTFT p50 Median time to first token (seconds): request dispatch to the first streamed token, reasoning or content. Excludes queueing; successful requests only. Lower is better.
TPS p50 Median output tokens per second after the first token: (output tokens − 1) / (last token − first token). Excludes prefill; only answers with 2+ output tokens. Higher is better.
Latency p50 Median end-to-end request latency (seconds): dispatch to last token. Excludes queueing and the reasoning follow-up call; successful requests only. Lower is better.
Latency p95 95th-percentile end-to-end request latency. The tail you'll see ~1 in 20 requests.
Errors/Refusals Rate of errors or refused answers. Lower is better.
